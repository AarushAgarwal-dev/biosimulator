Technical Report: BioSimulateAI

BioSimulateAI: An AI-Powered Platform for Automated Multi-Scale Biological Model Generation, Simulation, and Calibration

September 2026
Retrieval-Augmented Generation Evidence-Verified Compilation Multi-Scale Simulation Cellular Potts Model

Abstract

We present BioSimulateAI, an integrated web platform that turns plain-language descriptions of biological systems into executable, checked mathematical models. A language model (Purdue GenAI Studio by default; AWS Bedrock, OpenAI-compatible or local models are interchangeable) never writes equations directly: it fills a strict intermediate representation of species and processes, each tied to a verbatim quote from the description. The equations are then assembled deterministically and the model is accepted only after automatic checks: every stated interaction must have the right sign in the Jacobian, and the model must simulate to a finite, non-negative, bounded result. The same compiler runs without any language model on a rule-based path. Models can also come from Retrieval-Augmented Generation over curated databases (Reactome, STRING, OmniPath, SIGNOR, BioModels), from photographs of written equations, or from exact SBML import. Three simulation engines are coupled: an ODE compiler with SymPy code generation, a finite-difference PDE solver for reaction-diffusion, and a Cellular Potts Model for tissues. The platform also includes an organism-scale reaction-diffusion model of BMP patterning on the Drosophila embryo surface (Umulis et al. 2010). Published results are reproduced quantitatively: in the latest benchmark run all 21 test descriptions compiled correctly on each of the two tested language models, the SBML importer agrees with libRoadRunner to better than 10⁻⁴ on 8 curated BioModels entries, the two published-model presets reproduce their papers' figures, and the embryo model passes 15 of its 17 checks against the 2006 and 2010 papers. A closed-loop agent refines models toward experimental targets, and MAPLE-style extraction pulls parameters from the literature with hallucination-detection validators.

Keywords: biological modeling, verified model compilation, multi-scale simulation, retrieval-augmented generation, large language models, BMP morphogen patterning, cellular Potts model, ODE, PDE, systems biology, model calibration, reproducibility

1. Introduction

Mathematical modeling of biological systems has become indispensable in modern systems biology and pharmacology. However, constructing quantitative models remains a highly manual, error-prone process that requires deep expertise in both biology and applied mathematics. Researchers must manually identify relevant interactions from literature, translate them into differential equations, estimate kinetic parameters from scattered experimental data, and iteratively validate the resulting model against experimental observations.

Recent advances in Large Language Models (LLMs) and Retrieval-Augmented Generation (RAG) present an opportunity to automate significant portions of this workflow. By grounding LLM outputs in curated biological knowledge bases, we can reduce hallucination risk while preserving the flexibility of natural-language model specification. Here we present BioSimulateAI, a platform that integrates these technologies into a cohesive pipeline spanning text parsing, model compilation, multi-scale simulation, and AI-driven calibration.

Our contributions are fourfold: (1) an evidence-verified compiler in which a language model only fills a strict intermediate representation, every process must quote the description, and the deterministically assembled equations are checked before they are shown; (2) a multi-scale simulation engine coupling ODE, PDE, and Cellular Potts Model solvers through a time-scale-separated coordinator; (3) a MAPLE-inspired calibration pipeline with structured Pydantic schemas and hallucination-detection validators for literature-based parameter extraction; and (4) reproductions of published models, including the organism-scale BMP patterning model of Umulis et al. (2010), checked quantitatively against the papers' figures.

3. Natural Language Parsing & Blueprint Compilation

The system accepts free-text descriptions of biological processes and compiles them into structured JSON blueprints that drive downstream simulation. The compiler is built so that a language model can help read the text but cannot silently invent the mathematics: the model's only output is a constrained intermediate representation (IR), the equations are assembled from it by deterministic code, and the result is checked before it is shown. The same pipeline runs with no language model at all, on a rule-based extractor.

3.1 The Intermediate Representation

The IR lists species (with initial values and optional diffusion), named parameters (each marked as taken from the text or defaulted), imposed stimuli, and processes of five kinds: production, degradation, conversion (optionally enzyme-catalysed), binding, and custom rate laws. Activation and inhibition are attached to the process they regulate, and statements the model cannot represent are listed as unmodelled rather than dropped. Every process carries a verbatim evidence quote from the description, or is explicitly marked as an assumption with a stated reason. The language model is asked for JSON that satisfies a strict schema; Purdue GenAI Studio models use the backend's structured-output mode (vLLM response_format for gpt-oss, Ollama format for the others). The client retries empty (null) responses, rate-limit and server errors, detects truncated output, and keeps its request rate below the service's per-user limit.

3.2 Validation, Repair and Assembly

An IR fails validation when a quote does not appear in the text, when the quote contains no wording of the process's own kind, when the only evidence for an interaction is a negated sentence ("A does not activate B"), or when a custom rate law does not vanish as its consumed reactant is exhausted. The errors are sent back to the model for up to two repair rounds; if the IR still fails, the rule-based extractor is used and the interface says so. A small set of deterministic repairs, each disclosed to the user, handles recurring model errors measured in live runs: a named molecule filed as an external stimulus becomes a species; a species that no quoted process involves is removed instead of receiving invented turnover; a catalyst's amount stays conserved; a process that repeats another from the same sentence is dropped so no rate is counted twice. A rule-based cross-check adds interactions the rules find but the model omitted, and equations written out in the text take precedence over the model's reading. The accepted IR is then turned into rate laws (mass action, Hill-type regulation) by code, not by the model.

Before a model is displayed it must pass: (i) a symbolic Jacobian check that every stated activation or inhibition has the right sign, (ii) a simulation that stays finite, non-negative and bounded, (iii) a coverage check that every entity named in the text is represented, and, for reaction-diffusion models, (iv) a check that the explicit time step respects the diffusion stability limit. The results appear in the interface next to the equations, together with the quote each process rests on and every assumption made. On a 21-description benchmark with numeric behavioural checks, the latest run compiled all 21 descriptions correctly on Purdue GenAI (gpt-oss:120b) and on AWS Bedrock (Mistral Large), and all 21 on the rule-based path. Photographs of written equations are transcribed by a vision model and then compiled exactly as written, without reinterpretation.

The output blueprint is a JSON object. Custom-kinetics models carry explicit rate laws; the compiler also attaches its provenance and verification report:

4. Retrieval-Augmented Generation from Biological Databases

To ground model generation in curated biological knowledge, we implement a RAG pipeline that retrieves real molecular interactions from five external databases and transforms them into natural-language descriptions that seed the parser.

Table 2. External databases integrated into the RAG pipeline.
Database Data Retrieved API Type Fallback
Reactome Pathway structures, contained reactions, reaction participants REST Content Service Mock pathway catalog
STRING DB Protein-protein interaction networks with confidence scores REST JSON API Sequential chain generation
OmniPath Directed signaling interactions with literature references (PMIDs) REST API Curated interaction lookup table
SIGNOR Curated signaling relationships with mechanisms and effects REST API Pathway-specific mock data
BioModels Published SBML mathematical models with XML content EBI REST API Curated model catalog

The RAG workflow proceeds in three stages: (1) Retrieval: the user queries a database through the sidebar interface, receiving structured results (pathway names, interaction edges, SBML model IDs); (2) Augmentation: retrieved data is transformed into natural-language biological descriptions and injected into the text input area; (3) Generation: the augmented text is parsed by the LLM or rule-based parser to produce a grounded blueprint. Each database connector includes a mock fallback that returns representative data when the external API is unreachable, ensuring the platform remains functional offline.

Design Decision: Why RAG Instead of Direct API-to-Blueprint?

We deliberately route retrieved interactions through the natural-language parser rather than directly constructing blueprints from API responses. This design choice preserves the user's ability to edit, augment, and correct the retrieved knowledge before compilation. It also enables the LLM to synthesize information from multiple sources and resolve conflicts between databases that may report different interaction types for the same protein pair.

5. ODE Compilation & Symbolic Mathematics

The ODE compiler turns a blueprint into a system of coupled ordinary differential equations. Blueprints that carry explicit rate laws (from the evidence-verified compiler, SBML import, photographed equations, or the published-model presets) are compiled exactly as written, with every species, parameter and flux name bound as its own symbol. Edge-only blueprints, such as those built directly from database interactions, are expanded with the Hill-function kinetics described below. The compilation is fully symbolic, implemented with SymPy, enabling automatic LaTeX rendering, parameter sensitivity analysis, and efficient numerical evaluation.

5.1 Hill-Function ODE Formulation

For each species $X_i$ in the blueprint, we construct a derivative expression:

$$\frac{d[X_i]}{dt} = s_i + \left(\sum_{j \in \text{Act}(i)} \frac{k_j \cdot [X_j]^{n_j}}{K_{d,j}^{n_j} + [X_j]^{n_j}}\right) \cdot \prod_{k \in \text{Inh}(i)} \frac{K_{d,k}^{n_k}}{K_{d,k}^{n_k} + [X_k]^{n_k}} - \delta_i \cdot [X_i]$$ (1)

where $s_i$ is a basal synthesis rate, $\delta_i$ is a degradation rate constant, $\text{Act}(i)$ is the set of activators of species $i$, $\text{Inh}(i)$ is the set of inhibitors, and $k_j$, $K_{d,j}$, $n_j$ are the Hill activation rate constant, half-saturation constant, and cooperativity coefficient, respectively. All parameters are represented as SymPy symbols, enabling automatic differentiation and LaTeX export.

5.2 Code Generation & Numerical Integration

After symbolic construction, the system of equations is lambdified into a NumPy-compatible callable function using sympy.lambdify. This function is passed to SciPy's solve_ivp with the RK45 (Dormand-Prince) adaptive time-stepping method. Parameter values are passed as a vector, enabling efficient sweeps and optimization without recompilation.

5.3 Parameter Fitting

For fitting model parameters to experimental time-course data, we implement a least-squares optimization using scipy.optimize.least_squares with box constraints (parameters ≥ 0). The objective function runs the full ODE simulation at target time points and computes residuals against the observed data.

6. PDE Solver for Reaction-Diffusion Systems

For spatial models, we solve 2D reaction-diffusion PDEs on a regular grid using an explicit Euler finite-difference scheme:

$$\frac{\partial u}{\partial t} = D_u \nabla^2 u + f(u, v), \qquad \frac{\partial v}{\partial t} = D_v \nabla^2 v + g(u, v)$$ (2)

The discrete Laplacian is computed using a 5-point stencil with Neumann (zero-flux) boundary conditions implemented via edge padding. Reaction terms $f(u,v)$ and $g(u,v)$ are specified as algebraic expressions in the blueprint and compiled to NumPy-vectorized functions via SymPy's lambdify. Initial conditions support random noise perturbation around a base value (for Turing instability onset) or localized spots.

The default demonstration system implements a Gierer-Meinhardt activator-inhibitor model:

$$f(u,v) = \frac{u^2}{v} - u + 0.02, \qquad g(u,v) = u^2 - v$$ (3)

with $D_u = 0.05$ and $D_v = 1.0$, satisfying the classical condition $D_v \gg D_u$ for diffusion-driven instability.

7. Agent-Based Modeling: Cellular Potts Model

The ABM engine implements a full Glazier-Graner-Hogeweg (GGH) Cellular Potts Model with Monte Carlo Metropolis dynamics. Each cell is represented as a connected domain of lattice sites sharing a unique cell ID. The system evolves by minimizing a Hamiltonian energy functional:

$$H = \underbrace{\sum_{\langle i,j \rangle} J(\tau_i, \tau_j)(1 - \delta_{\sigma_i, \sigma_j})}_{\text{adhesion}} + \underbrace{\sum_{\sigma} \lambda_V (v_\sigma - V_T)^2}_{\text{volume}} + \underbrace{\sum_{\sigma} \lambda_S (s_\sigma - S_T)^2}_{\text{surface}} - \underbrace{\sum_{\sigma} \lambda_{\text{chem}} \Delta c}_{\text{chemotaxis}}$$ (4)

7.1 Monte Carlo Dynamics

At each Monte Carlo Step (MCS), $W \times H$ random pixel copy attempts are made. For each attempt, a boundary pixel is selected and proposed for reassignment to a neighboring cell. The energy change $\Delta H$ is computed, and the copy is accepted with Boltzmann probability:

$$P(\text{accept}) = \begin{cases} 1 & \text{if } \Delta H \leq 0 \\ \exp(-\Delta H / T) & \text{if } \Delta H > 0 \end{cases}$$ (5)

7.2 Cell Behaviors

Beyond energy minimization, cells execute biological behaviors at each MCS: growth (target volume increase), mitosis (random-axis division when volume exceeds threshold), apoptosis (stochastic death), secretion/uptake (coupling to diffusible fields), and chemotaxis (biased migration up concentration gradients). The engine supports four preset configurations: cell sorting, tumor growth, wound healing, and PDAC tumor microenvironment.

8. Multi-Scale Coupling Architecture

The MultiscaleSimulator orchestrates coupled ODE-ABM-PDE simulations using time-scale separation. The coupling loop operates as:

9. Closed-Loop AI Feedback & Optimization

BioSimulateAI implements a closed-loop feedback system where the AI agent evaluates simulation outputs against user-defined behavioral targets and iteratively refines the model. The system supports four target metric types:

Table 3. Supported target metric types for simulation evaluation.
Metric Type Description Parameters Example
peak_time Time at which a species reaches maximum concentration min, max (time range) ERK peaks between 5–15 min
peak_value Maximum concentration reached by a species min, max (concentration range) ERK peak ≥ 0.6
decay_ratio Ratio of final concentration to peak concentration max (upper bound fraction) EGFR decays to < 20% of peak
steady_state Final concentration value value, tolerance U settles at 1.0 ± 10.0

When targets are not met, the refinement agent employs two strategies: (1) LLM-based refinement, where the full blueprint and failure messages are sent to the open-source LLM with instructions to adjust parameters or topology; and (2) rule-based refinement, which applies heuristic parameter adjustments (e.g., increasing activation rate constants when peak time is too late, strengthening negative feedback when decay is insufficient). A sensitivity-enhanced variant first runs local sensitivity analysis to identify the most influential parameters before applying adjustments.

10. MAPLE: Literature-Grounded Parameter Calibration

Inspired by Eliason & Popel's Model-Aware Parameterization from Literature Evidence (MAPLE) framework, we implement a structured pipeline for extracting quantitative calibration parameters from scientific literature. The key innovation is the use of Pydantic schema validation with targeted hallucination detectors that catch fabricated values and citations.

10.1 Structured Schemas

We define two primary schemas: SubmodelTarget (for isolated experiments constraining individual parameters) and CalibrationTarget (for clinical endpoints constraining the full model). Each schema includes:

  • Input Layer: extracted data values with verbatim source snippets, DOI-tracked citations, uncertainty quantification (SD, SEM, CI), and sample sizes
  • Forward Model Layer: specification of the mathematical relationship between inputs and the target parameter, chosen from 15 built-in model types
  • Relevance Assessment: indication match, species translation uncertainty, evidence type

10.2 Hallucination Detection Validators

Four validators run on every extraction:

  1. Value-in-Snippet: Checks that every reported numeric value appears verbatim in the quoted source text. Numbers are extracted from the snippet via regex and compared with floating-point tolerance. Flagged as "HALLUCINATION DETECTED" on failure.
  2. DOI Resolution: Resolves each cited DOI via the doi.org API to verify the paper actually exists. Flagged as "FABRICATED CITATION" on failure.
  3. Unit Validation: Validates that reported units match recognized biological unit patterns (rates, concentrations, cell densities, etc.).
  4. Forward Model Execution: Compiles and test-executes the specified forward model with dummy parameters to catch malformed code or non-finite outputs.

10.3 LLM Extraction with Retry Loops

The extraction pipeline runs up to 3 attempts per parameter. On each attempt, the LLM response is parsed as JSON, validated against the Pydantic schema, and run through all four validators. If validation fails, the error messages are appended to the prompt for the next attempt, implementing a form of in-context error correction. If all retries are exhausted, the system falls back to a demonstration target with known-good provenance.

11. Frontend & Visualization

The frontend is implemented as a single-page application using vanilla HTML, CSS, and JavaScript, with three external libraries for specialized rendering:

  • Cytoscape.js renders the interaction graph. Arrows are derived from the equations themselves (the sign of each partial derivative), not drawn separately; weak influences are folded away by default and a "Show every connection" toggle draws all of them.
  • Chart.js renders ODE time-series data as responsive line charts with hover tooltips.
  • KaTeX renders the compiled LaTeX equations in the Equations tab.
  • Canvas 2D renders PDE heatmaps with a plasma colormap palette and ABM lattice visualizations with per-cell-type coloring.

The interface is organized into tabs: Blueprint (graph, provenance of every process and the verification results), Equations (LaTeX), Simulator (parameters, parameter exploration and visualization), Embryo BMP (the organism-scale model of Section 12 with live runs and its validation table), Feedback (optimization logs and target progress), Agent-Based (CPM lattice), MAPLE (extraction form and validation results) and Guides (captioned explainer videos rendered from the application's own outputs). A sidebar provides the text input, published-model presets, the database RAG interface, and the target constraint editor.

12. Organism-Scale BMP Patterning of the Drosophila Embryo

The Embryo BMP tab implements the organism-scale model of Umulis, Shimmi, O'Connor & Othmer (2010) [18]. Dpp/Scw heterodimers secreted in the dorsal region are bound by Sog/Tsg, shuttled toward the dorsal midline and released there when Tolloid cleaves Sog; a surface BMP-binding protein induced by signalling (the paper's best-supported feedback mechanism) sharpens the stripe. The reaction-transport equations (main-text Eqs 1–7; Supplemental Eqs 7–21 for the no-feedback and receptor-feedback variants and 52–61 for the surface-binding-protein feedback) and every printed rate constant, diffusivity and fitted parameter (Tables S1, S2, S3, S8 and S11) are used as published. They are solved on the perivitelline sheet of a 400 × 180 µm prolate spheroid (a finite-volume Laplace–Beltrami operator) and on the anterior-posterior midline cross-section, by the method of lines with a BDF integrator and an analytic sparse Jacobian; every run checks positivity and that ligand mass balance holds to a relative error below 10⁻³.

Three inputs were not published and are stated as assumptions in the interface: the FISH-derived Sog secretion field (the Fourier coefficients of Supplemental Eq. 82), the image-derived initial state, and a usable Sog secretion rate. Table S1 prints 1.36 µM/min, which, used literally, floods the embryo with Sog/Tsg and abolishes the stripe; the default therefore uses the 400 nM/min of the fully specified 2006 predecessor [17], and the printed value remains selectable. The paper fitted the model separately for its reconstructed embryo (Table S8, the default) and for the ellipsoid (Table S11); both sets are available. To verify the solver independently of these choices, the same code reproduces the 2006 model's published dorsal-midline curves (Supplemental Fig. 13) to within 12% from 30 minutes to steady state.

The two embryo checks that fail are informative. Before about 20 minutes, Sog/Tsg secreted in the lateral neuroectoderm floods the dorsal side of the model and holds the signal near zero until Tolloid clears it, whereas the paper's Fig. 4F already reads 16.8 nM at the dorsal midline at 15 minutes; the 60-minute level is reproduced (37.8 nM with the ellipsoid refit, against 37.9 nM). Halving Sog secretion for sog+/− widens the stripe, measured at 20% of the wild-type maximum, by 18.6 cells in the model against the 2–4 nuclei measured. Both depend on the unpublished Sog field and initial state. Claims about the paper's 3D model, such as the Fig. 4F time course and the ability of the no-feedback parameter set to form a stripe, are evaluated on the embryo surface; the one-dimensional cross-section, which treats the central Tsg source as if it covered the whole anterior-posterior axis, is shown for reference.

14. Discussion

14.1 Limitations

Several limitations should be noted. The rule-based compiler covers a defined set of phrasings; descriptions outside it need a language model, and the language models remain non-deterministic, so one benchmark run's score does not guarantee the next. The embryo model cannot reproduce the early Fig. 4F time course or the magnitude of the sog+/− phenotype without the unpublished inputs described above. The fold-change preset after Lyashenko et al. is a reduced model and is labelled as such. The PDE solver uses an explicit Euler scheme, which imposes stability constraints on the time step relative to the grid spacing and diffusion coefficients. The ABM engine, while featuring a full Hamiltonian formulation, does not currently implement elastic or persistence-based motility models.

14.2 Design Decisions

A key architectural choice was the blueprint-centric design: all simulation engines consume the same JSON blueprint schema, enabling seamless switching between ODE, PDE, and ABM representations. This also enables the closed-loop agent to modify the blueprint and re-simulate without engine-specific knowledge. Another critical decision was implementing comprehensive fallback systems at every level (mock database responses, rule-based parsing, and demo calibration targets), ensuring the platform remains fully functional without network access or an API key.

14.3 Future Work

Future extensions include: integration of stochastic simulation algorithms (Gillespie SSA) for low-copy-number species; import of SBML events and delays, which are currently reported but not translated; the non-uniform Tld and Tkv cases of the embryo model once image-derived fields are available; GPU-accelerated PDE solvers for larger grid sizes; and a DPO (Direct Preference Optimization) training loop that uses the refinement history to fine-tune the LLM agent's parameter adjustment strategy.

15. Conclusion

BioSimulateAI shows that language models can make biological modeling faster without being trusted blindly. The model reads the description, but every process it proposes must quote the text, the equations are built by deterministic code, and the result is checked for signs, boundedness and coverage before anyone sees it. Grounding in curated databases, exact SBML import and quantitative reproductions of published models give researchers a way to see where the system agrees with the literature and where, and why, it does not. The platform's blueprint-centric architecture enables transitions between modeling scales (ODE, PDE, ABM) and supports iterative AI-driven refinement toward user-defined experimental targets. All components are accessible through a browser interface with no installation required.
